このアプリは何をするもの？

受付で使っていた紙の会員申込書・退会届を、iPad 1枚で完結させるアプリです。 手書き・印刷・保管の手間を減らし、内容も金額もミスなく揃えられます。

📝

入力

お客様情報・プラン・金額を画面で入力

✓

確認

契約条項に1つずつチェック（全部チェックで次へ）

✍

サイン

指でその場に署名

🖨

PDF

A4の紙の形で保存・印刷（AirPrint対応）

成果 ①

契約書テンプレートを7種類

「テンプレート」＝契約書のひな形です。種類ごとに条項の文章・金額・チェック項目を持っています。

会員（クレジット）会員（クレジット・学割） HV定額（クレジット）会員（現金） 会員（現金・入会日あり）HV定額（現金） 退会届（停止届）
  • お預かりした本物のPDFの文言・金額のまま作成
  • 受付では選んで使うだけ。「テンプレート管理」から文章修正も可能
成果 ②（一番大事な所）

「☑チェック＋サイン」の仕組み

確認画面（お客様に見せる）

  • 契約の条項を1つずつ☑チェック
  • 全部チェックしないと先へ進めない
  • そのままサイン画面へ

PDF（保存・印刷）

  • 「ご確認事項」に☑＋条項の全文
  • 最後にご署名（手書き画像）
  • 紙の契約書と同じ見た目

＝ クレジット契約の6条項（申込・特典・6ヶ月退会・決済・天災・同意）も、この形で全部入っています。

成果 ③

退会届＋新しい入力タイプ

退会届は「理由を複数チェックで選ぶ」など、これまでと違う形でした。そこで入力タイプを2つ増やしました。

▼

選択肢（プルダウン）

1つだけ選ぶ。例：退会区分（会員／定額）

☑

複数選択（チェック）

当てはまるものを全部。例：退会理由19項目

  • 従来の 文字／電話／日付／複数行 に加わりました
成果 ④（つまずきポイント）

「読み込む」が最新文に更新

＜直す前＞

同じ名前のテンプレートは追加しないだけ。 →昔読み込んだ古い契約文がそのまま残る問題が発生。

＜直した後＞

「標準を読み込む」を押すと、既存の標準も最新の正式文に上書き更新。 「○件を追加／○件を更新しました」と表示。

  • 文章を直したら、もう一度「＋ からだラボ標準を読み込む」を押せば全端末に反映
成果 ⑤

顧客管理ページ

作った申込書から、お客様の一覧を自動でまとめます。

  • 店舗ごとにグループ分け
  • カルテ番号順に並ぶので探しやすい
  • クリックすれば、その人の申込書（PDF）をすぐ表示
中身を少しだけ（初心者向け）

次にやるとき ①

契約書を増やす・直す手順

ファイル js/karada_templates.js に、ひな形を1つ書き足すだけ。

// 新しい契約書テンプレートの例 tpl({ name: "会員申込書（新プラン）", // 画面に出る名前 category: "会員・クレジット", // 分類 body: BODY_KAIIN, // 冒頭の説明文 plans: planKaiin(), // プランと金額 checks: [ // ←これが☑チェック条項 chk("プレミアム会員 5,500円（税込）を申し込みます。"), chk("特典：通常6,270円→2,970円 …"), chk(DOUI), // 同意文 ], }),

書いたら →「テンプレート管理 → ＋ からだラボ標準を読み込む」で反映。

次にやるとき ②

公開（みんなが使える状態に）

  • 変更したファイルを 保存（コミット）して、作業用の枝（ブランチ）に push
  • gh-pages という公開用の場所にコピーして push すると、URLに反映
  • 反映まで 1〜2分。iPadは再読み込みすれば最新に
# ざっくりの流れ（やっている作業） git add . # 変更をまとめる git commit -m "説明を書く" # 保存 git push origin 作業ブランチ # 自分の枝へ送る # → 公開用(gh-pages)へコピーして push すると本番反映
よくある質問

困ったときは

  • 文章を直したのに変わらない
    →「標準を読み込む」を再度押す＋画面を再読み込み
  • チェックして進めない
    → 条項を全部チェックすると進めます（仕様）
  • 金額や文言が原本と違う
    → テンプレート管理 → 編集 で直せます
  • PDFが欲しい
    → 印刷 →「PDFとして保存」を選択
