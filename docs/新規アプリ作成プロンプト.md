ここから

株式会社まごころグループの業務アプリを1つ新しく作ってください。
このリポジトリ（timecard_app）のルートにある **CLAUDE.md が絶対のルール**です。まず CLAUDE.md を読み、以下に従ってください。

## 作り方（必ずこの順で）

1. `timecard-system/` を標準実装としてコピーして `<アプリ名>-system/` を作る
   - コピー元: 設定ファイル一式（package.json / tsconfig / tailwind / next.config / postcss / .npmrc / vercel.json / .env.example / .gitignore）、`src/components/`、`src/lib/{prisma,session,utils,auth-actions}.ts`、`src/auth.ts`、`src/auth.config.ts`、`src/middleware.ts`、`src/types/`、`src/app/layout.tsx`、`src/app/globals.css`、`src/app/login/`、`src/app/(app)/{layout,error}.tsx`、`src/app/(app)/account/`、`src/app/api/auth/`、`src/app/api/setup/`、`prisma/seed.ts`、README.md / DEPLOY.md の形式
   - package.json の name とポート番号（3002, 3003 は使用済み。次は 3004）を変える
   - Next.js / React / next-auth / prisma のバージョンは timecard-system と同じにする
2. Prisma は `previewFeatures = ["multiSchema"]`、`directUrl = env("DIRECT_URL")`、`schemas = ["<アプリ名>"]`、全モデルに `@@schema("<アプリ名>")`。Supabase の1プロジェクトを他アプリと共有する
3. ログインは「ユーザーID（loginId）＋パスワード」。権限は ADMIN（本部）と STAFF（店舗スタッフ）。店舗スタッフの閲覧範囲は**サーバー側**（`requireUser / requireAdmin` と server action 内）で必ず制限する
4. 店舗マスタは `timecard-system/src/lib/constants.ts` の `ALL_STORES`（本部を含む）と `detectBrandAndStore()` を流用する
5. 画面は 左サイドバー（PC）／上部メニュー（スマホ）の共通シェル、`PageHeader` → `Card` の構成。文言はすべて日本語
6. フォームは `useActionState` + server action。action は `{ error }` か `{ success, message }` を返し、成功時はクライアントで `router.refresh()`
7. 一覧で件数が多くなる画面には、ブランド／店舗／スタッフなどの**絞り込みタブ**（クライアント側で即時切り替え・押しやすい大きさ）を付ける
8. `/api/setup?key=<AUTH_SECRET>`（テーブル作成＋初期データ。既存データは絶対に消さない）と `npm run db:seed` を用意する
9. `README.md`（機能一覧・ローカル起動）と `DEPLOY.md`（Supabase + Vercel の手順。Root Directory = `<アプリ名>-system`）を書く。CLAUDE.md のアプリ一覧の表にも1行足す

## 絶対にやらないこと（CLAUDE.md の4章。実際に不具合になった）

- `loading.tsx` を置かない
- server action の中で `revalidatePath` / `revalidateTag` を呼ばない
- server action から同じパスへ `redirect()` しない
- DBを読むページには `export const dynamic = "force-dynamic"` を付ける
- `.env`・パスワード・接続文字列をコミットしたりチャットに貼ったりしない

## 動作確認（完了の条件）

- `npx prisma db push` → `npm run db:seed` → `npx tsc --noEmit` → `npm run build` がすべて通る
- Playwright でログイン〜主要操作（登録・編集・一覧の絞り込み・権限による制限）を通しで確認し、スクショで見た目も確認する
- 終わったら `main` にコミット・プッシュし、Vercel での公開手順（Import → Root Directory → 環境変数 DATABASE_URL / DIRECT_URL / AUTH_SECRET / AUTH_TRUST_HOST → Deploy → `/api/setup`）を画面操作レベルで案内する

## 進め方

- 仕様が曖昧なところは、作り始める前に選択肢を示して確認する
